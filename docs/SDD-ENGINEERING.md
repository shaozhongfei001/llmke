# SDD 执行规范 V1.1.0

## 可冻结的对象

冻结合同与控制文件的准确版本/摘要；不把“看过文档”当批准，也不把构建成功当业务验收。当前业务事实未确定的点记录 P0、复用登记或质量批准状态，技术合同可明确“缺失则拒绝”。

## 一条切片的完整链

1. 需求/旧行为：目标场景、调用者、运行时路由、发布源码、存量数据；为每个资产分配 ID。
2. 决议：保留/适配/重写/退役，明确差异和原因，引用 BL/CR；改变路径、坐标、枚举、身份、错误或流语义均检查消费者和历史数据。
3. 合同：registry登记，跨合同复用共享schema；状态机/跨字段条件由运行时不变量和测试表达，不能仅靠description。
4. 生成和校验：空目录生成；完整输出集合、输入/依赖/工具链哈希；OpenAPI/JSON Schema引用合法；共享样本同时跑生产者/消费者。
5. 实现：优先包裹原内部能力；Java四层、Python无业务库写入；允许精简适配，不允许靠重命名掩盖行为变化。
6. 回放/迁移：原行为特征、变更批准后的期望、坏数据/迟到/权限/故障；DB在同版本恢复副本迁移并新旧程序双向读写和回退。
7. 门禁：Loop以当前源码/合同/制品运行指定测试；满足前置条件才执行；独立QA与业务签署走受信外部证据。

每条可交付能力必须能追溯：legacy_asset → decision → contract@hash → target_module → characterization → compatibility/migration → gate。未映射资产阻断其所属切片，不阻断无关诊断。

## 变更

源合同改动需CR，记录触发、旧新行为、调用方/数据影响、回退、owner和批准。运行 `make contract-all`、共享样本和相应负例；重新冻结是新基线，不重用旧QA。治理资料与源实现改变会使当前源码证据失效，历史签署保留在历史版本。

## 工期

三个测量切片：授权检索、文件→代次激活/删除、问答→证据/持久化。逐资产记录理解/适配/实现/回归/迁移人日、缺陷与余量，再重估；12个目录或506记录不能推出90%复用与21周。
