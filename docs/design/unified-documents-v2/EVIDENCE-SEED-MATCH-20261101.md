# 查询侧种子识别：简称能认出来，且真的能走图（2026-11-01）

## 问题

`find_seeds` 原来只做"实体名是 query 子串"的精确匹配。真实提问很少写全称：
问「华东精密的授信额度」，库里实体叫「华东精密制造有限公司」→ `seeds=[]` →
`decide_route` 回退稠密 → `require_graph` 直接判失败。这不是检索坏了，是**认不出种子**。

## 改法（两层，缺一不可）

### 第一层：匹配（`seed_match.py`）

- 精确子串优先（行为不变）；
- 去掉机构后缀后再比（`华东精密制造有限公司` → `华东精密制造`）；
- 允许**中间省略的简称**：取实体核心名里"最长且出现在问句中的连续片段"
  （`华东精密电子` 常被叫 `华东电子`，前缀匹配盖不住）；
- 最短 4 字（`华东` 这种不认，否则一处简称能匹配半个库）；
- **歧义按"解析出的实体 id"判，而不是按名字个数**：引擎里同一实体常有
  `ent:名称` 与原名两条登记，按名字数会把一个实体误判成两个而放弃种子。

宁可少认（回退稠密仍可用），不可错认（把查询引到错误的子图）。

### 第二层：执行（`pipeline.retrieve`）

只修匹配还不够。实测：

```
问「华东精密制造有限公司的授信额度是多少」→ 计划 GRAPH → 执行 GRAPH → 答 3000 万元
问「华东精密的授信额度是多少」            → 计划 GRAPH → 执行 DENSE_FALLBACK → 无答案
```

原因是**引擎自己还要再认一次实体**：它拿原始 query 做实体链接，简称认不出，内部回退稠密。
所以 `pipeline` 在调用引擎前把种子的**规范名补进查询**（不改写原问句，只追加）：

```
engine_query = "华东精密的授信额度是多少 华东精密制造有限公司"
```

补后：计划 GRAPH → **执行 GRAPH** → 答 `3000万元`，引用 1 条，`passed=True`。

## 真实验证（索引 `.artifacts/hippo-cjk`，50 个登记名）

| 问句 | 旧 seeds | 新 seeds | 方式 |
|---|---|---|---|
| 华东精密制造有限公司的授信额度 | 1 | 1 | exact |
| 华东精密的授信额度 | 0 | **1** | normalized |
| 江南装备的信用评级 | 0 | **1** | normalized |
| 海川电子的授信额度 | 0 | **1** | normalized |
| 多指标对账口径是什么 | 0 | 0 | none |

最后一条**仍然为 0**：该概念没被抽取成实体（抽取侧的缺口），不是匹配规则太死。
这一区分很重要——两种缺口的修法完全不同。

## 测试

- `tests/test_seed_match.py` 11 项：精确/去后缀/前缀简称/中间省略/歧义放弃/同实体双名不算歧义/
  太短不认/无实体/diagnose 文案；
- `tests/test_seed_expansion.py` 3 项：简称问句补规范名、全称问句不重复追加、无种子时原样透传。

## 边界（诚实列出）

- **只覆盖"实体名出现在问句里"** 的情况。概念式问句（"多指标对账口径是什么"）仍无种子，
  要解决得靠抽取侧把概念抽成实体，或引入向量/同义词召回——都未做；
- 简称匹配是**连续片段**，不处理乱序（"精密华东"认不出）；
- 最短 4 字是经验值，对两字实体（"中行"）不适用；
- 追加规范名会改变引擎看到的 query，可能影响稠密分支的排序——只有简称命中时才追加，
  且实测端到端答案与引用正常。
