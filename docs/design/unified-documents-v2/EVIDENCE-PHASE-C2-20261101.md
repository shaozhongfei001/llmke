# 阶段 C2：同语料 full vs delta 双建对比（2026-11-01）

结论先说：**块集合完全一致，事实集合差 1 条（50 共享 + 1 只在 delta）**；
而 full-vs-full 重跑**完全相同**，所以这 1 条不是随机抖动，是两条路径的**系统性差异**。

## 方法

同一语料（329 的 2 块 + 新增条款 1 段，共 3 块）：

| 快照 | 怎么建的 |
|---|---|
| `/tmp/dual-full` | 全量建（`HippoRAGEngine.build`） |
| `/tmp/dual-full2` | 全量再建一次（**基线噪声样本**） |
| 已有 delta 快照 | 从"333+329 的全量"里删掉 333、加入新增条款（`apply_delta`） |

对比工具 `scripts/v2_dual_build_diff.py`：块按 passage 哈希、事实按 `(chunk, s, p, o)`，
差异归因 `MISSING_CHUNK` / `EXTRACTION_DIFF`。

## 结果

```
full vs full2（基线噪声）
  chunks: shared 3，identical=true
  facts : shared 50，only_a 0，only_b 0     → IDENTICAL

full vs delta（同语料）
  chunks: shared 3，identical=true
  facts : shared 50，only_a 0，only_b 1     → DIFFERENT
  差异项：("董事会", "审议通过", "单笔授信")，只在 delta 侧
```

## 怎么解释这一条

- **不是随机抖动**：full 重跑两次一字不差（50 条事实全同），说明这套配置下抽取是确定的；
- **是批处理差异**：full 把 3 块一次性抽取；delta 是"删掉旧块后只对新增块 `index(to_add)`"，
  新增块单独成批。同一段文本在不同批次里被抽取，结果可以不同；
- **方向上看 delta 更全**（多抓到一条本应存在的三元组），full 漏了它。
  这不是"delta 降质"，而是"两条路径不等价"。

## 这条发现对灰度的意义

之前我们把"块数一致 + openie 条数对得上"当成增量成功的判据——**这条证据说明那不够**。
只要两条路径的抽取批次不同，事实集合就会有差异，而且差异是**确定的**（不是噪声），
所以不能用"多跑几次取平均"抹平，只能：

1. 把差异**登记成已知偏差**（当前 1/51 ≈ 2%，样本仅 3 块，不可外推到大库）；
2. 若要严格等价，delta 得按与 full 相同的批次抽取（会牺牲一部分增量收益，未做）；
3. 灰度判定必须带**差异清单**，而不是只看"块数/条数对不对"。

## 边界（不要外推）

- 语料只有 3 块、单次运行，**不能**据此给出大库的差异率；
- 只比了"抽取结果"，**没比检索质量**（同一 query 在 two 快照上的命中是否一致）；
- 基线噪声只采了 1 对样本（full vs full2 全同）；更严谨要多采几对，确认"确定性"不是缓存造成的假象；
- delta 快照是历史产物（10-31 建的），与今天的 full 之间存在代码/配置漂移的可能，未做时间对齐验证。
