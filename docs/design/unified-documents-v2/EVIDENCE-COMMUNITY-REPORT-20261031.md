# 社区与 global 报告（2026-10-31）

模块 `graph_engine_adapter/community.py`（7 项测试），真实运行 `scripts/v2_community_report.py`。

## 为什么不用引擎的社区实现

设计 §6.4 写的是：社区/global 由独立处理器消费**经原文和本体校验的标准事实导出**；
导出不足时状态应为 BLOCKED/NOT_READY，**不得用普通 RAG 顶替**。
所以输入是平台 `AssertionStore`，不是 HippoRAG 的内部图——引擎的社区是算法结构，
拿它当业务结论等于把算法当事实。

## 三步，职责分开

1. **导出**（`export_facts`）：只放行来源存在且在可见集合内的事实；其余逐条给原因
   （`NO_SOURCE` / `SOURCE_NOT_VISIBLE` / `EMPTY_OBJECT`），不静默丢弃；
2. **社区**（`build_communities`）：实体-实体**无向连通性**上做标签传播，
   遍历顺序按 id 排序、平票取字典序最小，**结果可复现**；孤点单独成社区并标 `isolated`；
3. **报告**（`build_report`）：每社区给出成员、代表事实、来源，再逐条校验引用能否回到真实来源；
   状态 `READY` / `PARTIAL` / `BLOCKED` 由"是否有事实 + 引用是否全部有效"决定。

## 顺手修掉一个渲染缺陷

社区报告里事实最初渲染成 `ent:北方重工配件厂 所属产业链 ent:汽车零部件`——因为
`name_of` 取排序后的第一个登记名，而 `ent:` 前缀恰好排在前。改为**优先取非 id 形式的名字**后
变成可读文本。这个缺陷同时影响回答段的上下文渲染，一并修好。

## Q 的变化

`biz:global 报告/引用失效识别` 由 NOT_IMPLEMENTED 转为真实检查（跑 `v2_community_report.py`，
缺引擎/载荷则 SKIP 并写明缺什么），Q 现 **27 PASS / 0 FAIL / 0 NOT_IMPLEMENTED**。

注意：Q 的"业务场景"清单清空**不代表能力全齐**——引擎侧仍缺的项由 `describe()` 承担，
`tests/test_q_acceptance.py` 现在强制检查 `describe` 里 NOT_IMPLEMENTED ≥ 1，
避免把两处口径一起清空。
