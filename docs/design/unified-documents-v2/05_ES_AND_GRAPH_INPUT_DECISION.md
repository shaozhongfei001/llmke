# 去ES与直接MD抽图：设计裁定

日期：2026-10-30。状态：设计已修订，产品实现与目标环境验证未执行。

## 1. 对用户建议的独立判断

| 建议 | 判断 | 落入本设计的具体规则 |
|---|---|---|
| 所有支持格式先经doc2md | 合理 | 一个原件解析入口，后续共享不可变三件套、IR和资产 |
| GraphRAG直接读取转换后的MD | 合理，但MD正文不能替代IR/表格/图片来源 | Graph直接读ParseArtifact，不查ES、RAG chunk或原件重解析 |
| GraphRAG跳过先做RAG切片 | 合理 | graph build与RAG build互不依赖；不同的上下文单元各自版本化 |
| 任意长MD整篇一次抽完 | 不作为通用设计 | 短文整篇；长文按结构和真实模型token预算开窗口；不得截断尾部 |
| 去掉ES | 目标合理，停用须有能力承接 | 默认目标profile不需要ES；全文/精确/混合检索和所有ES旁路用途完成迁移再停服务 |
| 一个知识库最终形成关联图 | 合理 | 同授权域同快照统一实体身份、支持来源、图与社区；文件不是最终孤立图边界 |

以上是架构判断，不能当成当前代码已实现的事实。少组件不是唯一目标；资源节省要与召回质量、构建成本、权限语义和离线交付共同核算。

## 2. 官方材料核对

2026-10-30读取官方网页：

1. GraphRAG Dataflow：先Compose TextUnits，再按text unit抽取实体关系，之后社区检测与报告；文本单元同时承担溯源。<https://microsoft.github.io/graphrag/index/default_dataflow/>
2. GraphRAG Inputs：可以提供documents DataFrame绕过文件loader；文档明确chunking仍继续执行。<https://microsoft.github.io/graphrag/index/inputs/>
3. Milvus 2.5.x Full Text Search：提供analyzer、BM25函数、稀疏倒排及与稠密检索结合的能力。该文档不能证明目标机当前Milvus已经具备或启用了这些能力。<https://milvus.io/docs/v2.5.x/full-text-search.md>
4. MySQL 8.0 ngram：支持CJK，默认bigram；自然语言、布尔和通配符行为有区别，停用词可能剔除含该字符的ngram。不能无对照替换ES中文检索。<https://dev.mysql.com/doc/refman/8.0/en/fulltext-search-ngram.html>

网页为核对时的在线版本；正式接入仍须锁定实际GraphRAG/Milvus/MySQL及分词器版本并登记制品hash。本包没有运行官方框架，也没有目标机版本证据。

## 3. 建议的新链路

doc2md统一解析并提交不可变产物后，两条流水线独立消费同一快照：

- RAG：结构化内容 → 召回chunk → dense/lexical/exact → 融合/精排 → 有来源的回答。
- GraphRAG：完整MD/IR → 抽取计划与窗口 → 文档内指代 → 全库实体链接/有向限定断言 → 社区 → 有支持组的报告 → local/global。

Graph抽取不需要预先向量化正文；实体候选召回、local或报告检索后续可能使用embedding，这是另一阶段的用途。也不要求把全知识库塞进一个上下文。社区来自关联图的算法分组，不来自“文件切片数”或“上传文件数”。

## 4. 抽取窗口必须保留的语义

1. 输入保留章节标题、表头、单位、脚注与适用范围；来自补充上下文的内容同样登记来源。
2. MD是完整固定证据基准；窗口记录字符区间，抽取结果不以窗口内临时offset冒充全MDoffset。
3. 计划的MD覆盖并集不得漏掉非空尾部；每个IR块都有抽取/非正文排除/未对齐状态。未对齐时不能发布“完整抽取”。
4. 输入hash、真实模型版本、tokenizer及提示词版本可复算；输入+预留输出不得越界。自动覆盖检查不证明实际模型执行或抽取召回率。
5. 不因相似或同名强行合并，不为追求连通率虚构边；没有业务联系的文件允许不同分量。

## 5. 去ES的落地判据

本轮确定“ES不属于核心合同必需依赖”，尚不签发“当前ES可立即停止”的运行结论。

| 必须有的证据 | 需要拿到的具体内容 |
|---|---|
| 职责全量去向 | 真实代码/config/API中全部ES读写与管理调用，每项对应替代实现或明确停用的非目标旧功能 |
| 中文与金融词项 | 产品名、法规条号、中文简称、AAA/AA、BP、正负调整、金额单位、精确标识的可人工核对检索题 |
| 检索效果 | 同doc2md快照、同模型/问题/精排下，旧检索与候选dense+lexical/exact逐题结果；留出集独立核验 |
| 权限与版本 | 同域/同代过滤、删除、撤权、邻近块回查，缺一个不能靠最终回答过滤补救 |
| 成本 | 目标语料量/并发下的构建、增量删除、P95、峰值RSS、CPU、磁盘与真正离线包净变化 |
| 迁移恢复 | 由解析产物重放、失败切回旧发布、干净机器断网安装，记录配置/包/commit映射 |

若候选不达既定业务判据，保留ES适配器并记录差值，不以“组件更少”为由宣布检索完成。未知的业务阈值与容量必须在评测前填入，不能看完结果再调验收线。
