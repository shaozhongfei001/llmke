# 跨可见范围合并检索（2026-11-01）

构建期隔离做完后立刻出现的新问题：用户同时属于 `dept-a` 与 `dept-b` 时怎么查？
分别查再手工拼，还是查一次？

## 为什么用 RRF 而不是加权分数

不同索引的相似度分数**不可比**：各自的 embedding 与图结构不同，尺度不一样，
直接比分数等于拿两把不同的尺子量同一段长度。

RRF 只用名次：`score = Σ 1/(k + rank)`，`k` 默认 60（原论文取值）。
单调、无需归一化、对各路分数尺度不敏感，这也是搜索引擎融合多路召回的标准做法。
**出现的次数比名次更重要**：一条内容被两个范围同时召回，分数天然高于只被一个召回。

去重键是归一化后的文本；平手按文本 sha256 排序，保证融合结果可复现。

## 真实运行（`.artifacts/scoped`，dept-a / dept-b，五级分类只对 dept-b 可见）

问题：「五级分类口径中的关注是什么意思」

```
scopes=['dept-a']              used=['dept-a']          n=3
   ## 授信台账 ...
   ## 授信台账 ...
   ## 授信管理办法 ...
scopes=['dept-a','dept-b']     used=['dept-a','dept-b'] n=3
   ## 授信台账 ...
   ## 授信台账 ...
   ## 五级分类口径 正常：借款人能够履行合同 ...
```

单范围用户**看不到**该文档（隔离仍成立）；双范围用户能取到——合并确实接上了两份索引。

## 一个必须说清的副作用

合并后「五级分类口径」排在**第 3**，前两条是授信台账。原因不是合并写错了，而是 RRF 的固有性质：
台账同时出现在 dept-a 与 dept-b 两份索引里，拿到两路共识加分；而五级分类只在 dept-b 出现，
只有一路分数。**RRF 奖励"多路共识"，不判断相关性**。

要让相关文档排上来，需要跨索引的语义重排（一个能看到全部候选的模型），本轮没做。

## fail-closed

- 清单里查不到的范围 → **跳过并记录**在 `scopes_missing`，不回退全量索引；
- 全部范围都查不到 → `reason=NO_RESOLVABLE_SCOPE`、`passed=False`；
- 某个范围加载/检索抛异常 → 记进 `errors`，其它范围照常返回（不能一条坏路拖垮整次查询）。

## 测试

`tests/test_merged.py` 7 项：多路共识优先、平手可复现、双范围合并、缺失范围跳过并记录、
全部缺失 fail-closed、单路异常不影响其它路、空范围集合拒绝。

## 边界

- 只做去重与名次融合，**不做语义重排**；
- 每个范围加载一次引擎，范围多时内存/延迟线性增长（调用方应缓存 retriever）；
- 未做范围权重（重要库加权）、未做跨范围去重的来源合并（同一内容来自多个范围的 sources 未合并）。
