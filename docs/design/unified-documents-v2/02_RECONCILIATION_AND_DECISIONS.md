## 2. 本次架构判断与修改

| 原约束/建议 | 本次处置 | 具体理由 |
|---|---|---|
| 双栈复用与“不重写deepdoc” | 保留可用内核，入口统一doc2md；部署可收敛 | 避免重新实现解析；不将90%复用率/21周当本轮已验证工期 |
| 契约优先 | 保留，但新增平行V2 | 旧对象封闭，原语义不可静默改写 |
| 固定可解释检索 | 保留 | 图检索是明确路线，不让引擎自由绕过平台鉴权/引用 |
| ES默认与ES中转建图 | 修改 | 标准产物仓承担输入；ES只留迁移适配，不再核心必选 |
| 所有下游共用同一chunk | 不采用 | 共用同一解析版本；RAG召回与Graph抽取有不同上下文需求 |
| Graph整篇MD抽取 | 有条件采用 | 短文可整篇；长文必须预算、覆盖与结构窗口 |
| 社区仅可选后续 | 修改为当前目标必选能力 | 用户要完整知识库与跨文件关联，不能以旧范围条款排除 |
| 直接绑定官方GraphRAG或自研 | 不采用 | 首适配HippoRAG，平台合同与插件分离；切换成本仍需实证 |
| doc2md 19项候选增强 | 只吸收相关结构/溯源思想 | 不将其未实现部分、银行连接器或全量UI纳入本次已交付能力 |
| 形式合法等于语义正确 | 明确拒绝 | schema可拦空来源/错摘要，不能自动判断加30BP是否被模型说成减30BP |

## 3. 修正先前设计表达的责任

此前在未核对doc2md冻结合同和真实出口前作“已确认”式答复不充分；本包以原MD证据锚、原IR和实际入口接线状态修正。此前开发提示词依赖的架构边界不能继续自动派工。

新合同也不能代替真实接线、金融语义验证和目标机发布。接口设计可替换，与两个真实引擎切换已验证，分别记账。

## 4. 材料不足

最新doc2md源码/制品与全格式输出；HippoRAG最终锁定版本及离线依赖；真实DDL和恢复副本；目标机器、并发/容量/质量阈值；现部署ES职责全量清单与检索基线；本体当前批准状态及实际社区输出。未看到这些，不预先宣称“可立即关ES”“已兼容HippoRAG”“可投产”。
