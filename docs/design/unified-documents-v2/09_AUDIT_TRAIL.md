# 09 审计日志设计

> 状态：**设计草案**（当前只有 metrics，没有审计）。留存期为**建议值**。

## 1. 审计与指标的区别

- **metrics** 回答"系统运行得好不好"（QPS、延迟、错误率），可聚合、可丢。
- **audit** 回答"谁在何时对什么做了什么"，逐条、不可改、不可丢。

两者不能互相替代。

## 2. 必须记录的事件

| 事件 | 关键字段 |
|---|---|
| 查询 | 人、空间/知识库、查询文本哈希、命中块 ID、引用文件 ID、答案是否通过校验 |
| 权限拒绝 | 人、请求资源、拒绝原因（不记录资源是否存在） |
| 撤权/删除 | 操作人、文件/版本、围栏版本号 |
| 重建与发布 | 触发人、快照 ID、前后指针、耗时、结果 |
| 配置变更 | 人、项、旧值/新值的哈希 |
| 登录/令牌 | 人、结果（成功/失败）、来源 IP |

不记录：答案全文、文档正文（避免审计库变成第二份数据副本）。

## 3. 字段（统一结构）

```
ts, trace_id, actor{id,type,ip}, action, resource{type,id,version},
decision(allow/deny), reason_code, query_hash, hit_ids[], snapshot_id
```

## 4. 写入

- **异步**：业务请求不等待审计落盘；队列满时降级为本地文件，再补写。
- **追加写**：只 INSERT，不 UPDATE/DELETE。
- **防篡改**：每条记录带前一条的哈希（哈希链），定期把链头写入独立位置。
- 失败可见：补写失败计数进 metrics，并告警。

## 5. 存储与留存

- 表按月分区；**建议留存 180 天**，到期归档，不直接删除。
- 审计库与业务库分离账号，业务账号只写不读。

## 6. 查询与授权

- 只允许安全管理员按人/时间/资源检索。
- 普通用户可查"自己的操作记录"。
- 导出需二次确认并本身被审计。

## 7. 未实现与验证
