## 3. A2：ORM 分析器修复（本轮唯一的工具改造）

修掉第六轮实测的两个缺陷：

| 缺陷 | 修复前 | 修复后 |
|---|---|---|
| R1 `association`/`collection` 内层列 | 计入**父表**，污染覆盖率 | 进入独立的 `nested_map` |
| R3 同名 `property` 两条映射 | 后者静默覆盖，先出现列**丢失** | 保留首个 column，冲突写入 `conflicts`（含 kept/dropped） |

**验证**：`tools/orm_parser_selftest.py` → **6/6 PASS**，三条样例的期望已从「记录缺陷」改为「验证修复」。

**对覆盖率的影响（重要且诚实）**：

| 项 | 修复前 | 修复后 |
|---|---|---|
| 全 37 表覆盖率 | FULL 14 / PARTIAL 17 / NONE 3 / NO_MAPPER 3 | **完全相同** |
| 真实 mapper 中含嵌套映射 | — | **0 / 34** |
| 真实 mapper 中含同名 property 冲突 | — | **0 / 34** |

→ 说明：**这次的修复不改变 38% 这个数字**，因为现有 37 张表的 mapper 恰好都没用到嵌套或重复映射。
但风险是**潜在的**：若换一批代码（或未来新增 mapper），旧解析器会给出错误覆盖率。修复的价值在于「数字不再依赖运气」。

## 4. P0-03 追溯关系：8 个场景 ↔ 六类草案

| 场景 | 草案类 | 说明 |
|---|---|---|
| N1 跨域 + deny 优先 | **E2 + E3** | 一个场景覆盖两类：跨 KB/文件越权，以及 deny 覆盖 allow |
| N2 图干扰非干扰性 | **E6** | 改变未授权域数据，授权域社区结果必须不变 |
| N3 侧信道 | 扩展 | 社区数量/成员/分数、拒绝与不存在不可区分 |
| N4 缓存隔离 | 扩展 | 策略版本变化后不得命中旧结论 |
| N5 撤权残留 | **E4** | 撤权即时生效 |
| N6 FAQ 继承 | **E5** | 命中后按来源文档复核 |

| N8 邻近块/图片回查 | **E7** | 第六轮补齐；本轮确认覆盖 |

**为什么 8 个场景对应「六类」**：N1 同时覆盖 E2 与 E3（跨域读取与 deny 优先级本就在同一条判定链上），
N3/N4/N7 是**扩展场景**，不强行计入六类。**E2–E7 现已全部有场景，无 GAP。**
全部仍为 `SIMULATED` + `UNCONFIRMED_ASSUMPTION`。
