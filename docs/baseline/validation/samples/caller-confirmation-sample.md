# 调用方确认书（可填写样例）

> 用途：当路由导出与访问日志都不可得时，由**调用方**书面确认「这条接口我们确实在用/确实没在用」。
> 本文件是格式样例，示例内容为虚构数据。

## 0. 确认范围

| 项 | 内容 |
|---|---|
| 确认方 | `web-frontend-team`（示例） |
| 确认人 | `张三 / 前端负责人`（示例，需真实姓名与职务） |
| 确认日期 | `2026-10-21` |
| 覆盖的 `asset_id` 区间 | `API-0001` ~ `API-0120`（共 120 条） |
| 依据方式 | 调用方代码检索 / 网关配置核查 / 人工确认（三选一并写明） |

## 1. 逐条确认（示例 3 行 + 空白行）

| asset_id | method | path | 判断 | 调用位置（文件/网关配置/页面） | 备注 |
|---|---|---|---|---|---|
| API-0001 | POST | /agent/agentLogin | **IN_USE** | `web/src/api/auth.ts:42` | 登录页调用 |
| API-0034 | GET | /kb/list | **NOT_IN_USE** | 无引用（全仓检索 0 命中） | 2025 年后已由 /kb/page 取代 |
| API-0102 | POST | /retrieval_qa | **IN_USE** | 网关路由 `rag-qa` 转发 | 主问答入口 |
|  |  |  |  |  |  |
|  |  |  |  |  |  |

**判断取值只允许三种**：`IN_USE` / `NOT_IN_USE` / `UNKNOWN`。
`UNKNOWN` 是合法答案——**不确定就写 UNKNOWN，不要猜**。

## 2. 完整性要求

1. 必须写明「依据方式」：只靠记忆的确认不算证据；
2. `IN_USE` 必须给出可核查的调用位置（文件行号 / 网关配置项 / 页面路径）；
3. `NOT_IN_USE` 必须给出检索方式与命中数（例如「全仓 grep 0 命中」）；
4. 覆盖区间必须是连续且与 506 条清单对齐的 `asset_id` 范围；
5. 不得使用「大概在用」「应该没人用了」这类表述。

## 3. 无法提供时的替代证据（按优先级）

| 优先级 | 替代证据 | 说明 |
|---|---|---|
| 1 | 运行时路由导出 | 见 `route-export-sample.csv` |
| 2 | 网关/接入层访问日志 | 见 `access-log-sample.csv` |
| 3 | 调用方代码检索报告 | 附检索命令与输出摘要（含 commit） |
| 4 | 变更历史 | 该接口最后一次变更的 PR/工单，只能作为辅助 |

## 4. 声明

本确认书仅用于 P0-01 的「在用判断」，**不构成** KEEP/ADAPT/REWRITE/RETIRE 决议；
复用决议仍需 owner 按 `REUSE_DECISION` 流程签署。
