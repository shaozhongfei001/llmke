# 提交包 · index-owner（P0-04）

**要什么**：S1–S5 在真实四后端上的执行结果 + 双代余量实测。

## 材料清单

| # | 材料 | 格式 | 备注 |
|---|---|---|---|
| 1 | S1 部分后端失败 | 脚本 + 日志 | 四后端中任一个不可用时，激活必须**整体中止** |
| 2 | S2 切换中断 | 脚本 + 日志 | 中断后指针必须停在旧代 |
| 3 | S3 内容覆盖 | 脚本 + 日志 | 同 `(kb,file,config)` 内容不同需可区分（幂等键含内容哈希） |
| 4 | S4 迟到重试 | 脚本 + 日志 | 旧代任务必须被 `fencing_token` 拒绝 |
| 5 | S5 旧服务回退 | 脚本 + 日志 | 旧代继续写必须被拒 |
| 6 | 双代存储与内存余量 | 实测数字 + 资源曲线 | **P2 前必须给，不得推到 P3** |
| 7 | 历史引用不断链 | 快照保留验证 | 旧答案能否解析到被替换的快照 |

## 当前已有的（起点，非批准）

`evidence/p0-04-scenarios.json`：五场景模拟，5/5 通过、5/5 变异体被拒，分类 `SIMULATED`。
纯内存模型，**不证明**真实四后端一致性、余量、耗时。

## 验收规则

1. 每条场景给出「操作前后可读代次集合」，必须始终是**单元素**；
2. 失败场景必须证明**没有**跨代污染（新代数据不含旧代写入）；
3. 余量数字需含「双代共存期间的峰值」与机器规格；
4. 日志含环境标识与时间戳。

## 常见拒收

只给「切换成功」；用单后端冒充四后端；余量用估算值；模拟结果当实测。

## 对应与影响

P0-04 关闭、L1–L4 全部。

## 无法提供时必须做的决定

书面确认环境不可得，并选择：① P0-04 保持 OPEN（L1–L4 永久 BLOCKED）；
② 仅以模拟作为设计评审材料（明确不构成关闭）。
