# 提交包 · algorithm-owner（PDF 解析环境）

**要什么**：让「旧解析臂」可运行的材料，**或**旧系统对 6 份样本的参考输出。

## 路线 A：提供旧臂运行环境（首选）

| # | 材料 | 格式 | 备注 |
|---|---|---|---|
| 1 | `magic_pdf` 离线 wheel / 内网源 | 包 + 版本号 | 与 `torch`/`onnxruntime` 版本配对，版本敏感 |
| 2 | 版面/OCR 模型文件 | 目录 + 每文件 sha256 + 总大小 | 缺模型则构造解析器即失败 |
| 3 | 是否允许联网拉取 | 一句话 | 不允许则须完整离线包 |

已实测缺失：`magic_pdf`、`onnxruntime`、`cv2`、`tika`、`fitz`。
已实测阻断点：`image_parser.py:21` 在**构造期**加载 OCR（无模型时纯文本 docx 也起不来）。

## 路线 B：提供参考输出（无环境时可用）

对 `coordination/samples/` 的 6 份样本（3 PDF + 3 DOCX，已记录 sha256），
给出旧系统解析结果：

| 字段 | 要求 |
|---|---|
| 块数 | 整数 |
| 每块文本 | 原文 |
| `page_number` / `offset` | 每块 |
| 解析器版本 | 能对应到某个 commit 或制品版本 |
| 失败样本 | 明确写「失败 + 原因」，不要跳过 |

## 验收规则

1. 路线 A：能跑通 6 份样本，并输出**实际加载的解析器文件路径与 SHA256**；
2. 路线 B：参考输出需与样本 sha256 绑定，且注明产出环境；
3. 两臂对比时必须输出各自解析器路径并断言**不同**（防「自己和自己比」）。

## 常见拒收

只给「旧系统能解析」结论；给的是新版结果却标成旧版；无版本信息。

## 对应与影响

PDF 集成等价性（S1 最大缺口）。**不影响** P0-01…04 的门禁状态。

## 无法提供时必须做的决定

书面确认旧环境不可复现，并选择：① 以「参考输出」替代（需给出上面字段）；
② 明确「PDF 等价性不做，作为显式缺口」写进验收；
③ 暂缓 PDF 能力，先做 DOCX/TXT（但客户文档以 PDF 为主，需业务确认可接受）。
