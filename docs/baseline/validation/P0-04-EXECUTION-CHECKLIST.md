## 1. 环境与输入（缺一不可执行）

| 项 | 要求 |
|---|---|
| 存储 | MySQL、ES、Milvus、Neo4j 各一套，**同版本**，可双代共存 |
| 算力 | 能同时承载两代索引的机器规格（CPU/内存/磁盘需记录） |
| 数据 | 至少 1 个真实 KB：文件数 ≥ 50、块数 ≥ 1 万、含 3 类格式（PDF/DOCX/TXT） |
| 配置 | 解析/分块/embedding 版本号，写入 generation manifest |
| 观测 | 存储占用、内存峰值、各阶段耗时，至少 1 分钟一次采样 |

## 2. 五个场景的判定规则

| 场景 | 操作 | 通过判据 | 证据 |
|---|---|---|---|
| **S1 部分后端失败** | 生成 gen2 时人为使一个后端（如 Milvus）不可用，再触发激活 | 激活**整体中止**；可读代次集合仍是 `{gen1}`；失败后不得出现半切 | 激活日志 + 四后端可读代次快照 |
| **S2 切换中断** | 激活过程中 kill 进程 | 恢复后指针仍是 `gen1`；无跨代读 | 中断时间点 + 恢复后快照 |
| **S3 内容覆盖** | 同 `(kb,file,config)` 写两份不同内容 | 两份可区分（幂等键含内容哈希）；旧记录不被静默覆盖 | 两条写入的键与哈希 |
| **S4 迟到重试** | gen2 激活后，重放 gen1 的写任务 | 被 `fencing_token` 拒绝；gen2 数据**零污染** | 拒绝日志 + gen2 数据哈希前后对比 |
| **S5 旧服务回退** | 切到 gen2 后，让旧版本服务按 gen1 写 | 被拒（代次不匹配）；不得写入 gen1 导致"看起来正常" | 拒绝日志 + 两代数据量对比 |

**共同判据**：任一时刻「可读代次集合」必须是单元素；出现两代同时可读即失败。

## 3. 双代余量采集方法（P2 前必须完成，不得推到 P3）

| 指标 | 采集方式 | 输出 |
|---|---|---|
| 存储占用 | 双代共存期间，每 5 分钟记录各后端实际占用（索引大小 + 原始数据） | 时间序列 + 峰值 |
| 内存峰值 | 进程 RSS + 堆外内存（Milvus/ES 单独记录），1 分钟采样 | 峰值 + 持续时间 |
| 切换耗时 | 从"触发激活"到"四后端全部指向新代"的墙钟时间 | P50/P95（至少 10 次） |
| 回滚耗时 | 从决定回滚到"全部指回旧代" | P50/P95 |
| 容量余量 | （峰值占用 / 总容量） | 百分比，用于判断能否支撑下一 KB |

**验收标准（建议值，需 index-owner 确认）**：

1. 双代共存峰值 ≤ 总容量 **70%**；
2. 内存峰值 ≤ 规格 **80%**，且无 OOM；
3. 切换耗时 P95 ≤ **5 分钟**；
4. 回滚耗时 P95 ≤ **2 分钟**；
5. 上述四项在**同一批次**内同时达标，不得分批自证。

## 4. 历史引用不断链（R2）

| 步骤 | 判据 |
|---|---|
| 取 gen1 时期生成的 20 条历史回答 | 记录其引用块 ID 与快照指纹 |
| 切到 gen2 并删除 gen1 可读路径 | 历史回答仍能解析到原快照（或给出明确"已归档"状态） |
| 校验 | 20/20 可解析，且引用内容与原文一致 |
