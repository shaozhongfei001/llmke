### 2.1 `dialogue.user_id` 的严格结论

> 数据库是否真无此列，仍须 DDL 核验。源码缺失 ≠ 列不存在。

### 2.2 三种「无引用」必须区分

| 解释 | 例 |
|---|---|
| 列不存在 | 设计未落地 |
| 列存在但由框架自动填充 | `create_by` 常由 MyBatis-Plus 自动填充，手写 SQL 不写 |
| 列存在但由其他服务写入 | 本模块不引用 |

**同模块内不一致**：`re_embedding_task` 的 `gmt_create` 有引用，而 `re_embedding_file` 无 →
更可能是「部分表由别的路径写入」，而非「部分表没有审计列」。**必须 DDL 裁定。**

## 5. B4：解析边界与可核对样例（6/6 PASS）

口径：分母 = DO 非静态字段；分子 = `resultMap` 的 `column` 命中分母的个数。

| 样例 | 覆盖写法 | 结果 |
|---|---|---|
| F1 | `<id>` + `<result>` | PASS |
| F2 | property 在前 | PASS |
| F3 | `association` 嵌套 | PASS（属风险） |
| F4 | `collection` 嵌套 | PASS（主键丢失） |
| F5 | 手写 SQL + 别名 | PASS（解析不到） |
| F6 | 同名 property | PASS（先出现者被覆盖） |

**三个实测风险**：内嵌列被计入父表（虚高）、内层属性覆盖外层（虚低）、同名 property 丢列（虚低）。
**结论**：`14 FULL / 17 PARTIAL / 3 NONE / 3 NO_MAPPER` 是**映射完整度**，不是表结构；38% 是**下界**。
