# P0-03 设计提案：授权上下文与逐路执行

日期：2026-10-22　状态：**PROPOSED**，需 `security-owner` 裁定
依据（已实测，见 `P0-01-ROUTE-EXTRACT.md` / 源码）：

- `retrieval_graph()` 入参仅 `space_name / query / model_info / depth / top_k`，**不携带文件范围**；
- `perm_scope` 目前只用于越权兜底校验，**不是逐路执行约束**；
- 邻近块、图片回查、多版本扩召回会**再次取数**，可能绕过首次过滤；
- 原方案明确 FAQ 召回**不受**数据授权影响。

即：现在的授权是"入口检查一次"，而检索链路有 5 条会二次取数的旁路。

---

## 1. 核心不变式（一句话）

> **进入 LLM 上下文的所有内容，都必须已经过授权过滤；**
> **不能靠"最终引用再滤"来兜底**——那时内容已经进了模型。

这条不变式决定了下文所有设计：任何"先取回来再过滤"的路径都视为缺陷。

---

## 2. 授权上下文（AuthZ Context）

由网关签发、服务间传递、**不可由算法侧自行构造**：

```json
{
  "request_id": "uuid",
  "principal_id": "u-123",
  "principal_account": "zhangsan",
  "service": "rag-qa-service",
  "kb_scope": ["kb-1", "kb-2"],
  "file_scope": {"kb-1": ["f-1","f-2"], "kb-2": "*"},
  "authz_version": 17,
  "issued_at": "...", "expires_at": "...",
  "sig": "..."
}
```

约束：

| 项 | 规定 | 理由 |
|---|---|---|
| `authz_version` | 单调递增；撤权即 +1 | 缓存与长任务据此判断是否过期 |
| `file_scope` | 必须显式（`*` 表示整库授权） | 区分"整库授权"与"文件级授权"，图路径只能用前者 |
| 签名 | 服务私钥签，验证方只信网关公钥 | 防止算法侧伪造 |
| TTL | ≤ 5 分钟，且**请求期间不可续期** | 长任务用 version 判断，而不是续命 |

---

## 3. 五个执行点（不是一处）

| # | 执行点 | 现状风险 | 设计 |
|---|---|---|---|
| P1 | 检索入口（vector/fulltext/structure） | 通常有过滤 | 把 `kb_scope/file_scope` 编译成存储层过滤条件（不是取回后再滤） |
| P2 | **邻近块扩展** | 可能跨文件取相邻块 | 扩展前用 `file_id` 白名单二次约束；跨文件即舍弃 |
| P3 | **图片/附件回查** | 图片可能属于未授权文件 | 回查前校验图片宿主文件在 `file_scope` 内 |
| P4 | **图检索（graph）** | 入参无文件范围，**无法文件级隔离** | 见 §4：只对"整库授权"开放 |
| P5 | **缓存命中** | 缓存键若不含 `authz_version` 会串号 | 缓存键 = `(query, kb, file_scope_hash, authz_version)` |

补充 P6：**FAQ 召回**——按原方案不受数据授权影响，但必须满足：
FAQ 条目本身**不含**任何未授权文件的原文/引用；否则就是绕过。这条要 `security-owner` 明确。

---

## 4. 图检索的降级策略（必须显式，不能默默放行）

```
if file_scope[kb] == "*":           # 整库授权
    允许图路径
else:                               # 文件级授权
    禁用图路径，并在响应中标注 degraded_reason="graph_requires_kb_scope"
```

理由：`retrieval_graph()` 拿不到文件范围，**技术上无法做文件级隔离**。
与其"先查再滤"（违反 §1 不变式），不如明确降级并记录——这是可审计的诚实做法。

---

## 5. E1–E6 负例（做成自动化断言）

| 编号 | 场景 | 判据（可断言） |
|---|---|---|
| E1 | 同 KB 不同文件授权 | 用户只有 `f-1`，检索命中 `f-2` 的块 → **结果集必须为空**，且日志记录一次 `DENY_FILTERED` |
| E2 | FAQ 继承 | FAQ 命中条目若关联未授权文件 → 必须不返回（或该条目不得含文件引用） |
| E3 | 扩块跨文件 | `f-1` 命中后扩展相邻块落在 `f-2` → 扩展结果**不得包含** `f-2` 内容 |
| E4 | 图回填 | 文件级授权 + 图路径 → 必须走 §4 降级；若强行启用，返回内容必须仍全在 `f-1` 内 |
| E5 | 撤权后缓存 | 撤权后 `authz_version+1` → 旧缓存**必须失效**（缓存键含 version） |
| E6 | 绕过网关直调 | 无签名上下文直调服务 → **拒绝**（不是"按空权限继续"） |

每条都能落成集成测试；E1/E3/E6 可先用"人工构造上下文"验证，不依赖真实 SSO。

---

## 6. 与 P0-04 的交叉

- 长任务（重建索引）执行期间可能跨撤权：任务必须记录**发起时的 `authz_version`**，
  执行时若版本变化 → 中止并标记（不能"跑完再说"）；
- 这条与 `index_write_lease` 的 token 校验是同一类"时间维度防重放"问题。

---

## 7. 需要 `security-owner` 裁定的点

| # | 问题 | 影响 |
|---|---|---|
| 1 | 权限粒度：文件级 / 目录级 / KB 级（原方案三选一未定） | 决定 `file_scope` 结构 |
| 2 | 用户 / 部门 / 机构组授权冲突时的合并与拒绝优先级 | 决定过滤条件生成 |
| 3 | FAQ 是否继承来源约束（原方案说不继承） | 决定 E2 的期望结果 |
| 4 | 图路径降级是否可接受（§4） | 决定是否必须改 `retrieval_graph` 签名 |
| 5 | 撤权后已进入上下文的内容如何处理（无法回收，只能缩短 TTL） | 决定 TTL 上限 |

裁定后，E1–E6 才可写成正式测试；在此之前写测试只是把假设固化成"通过"。
