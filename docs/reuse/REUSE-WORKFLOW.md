# 原资产复用与数据库借鉴流程

1. LD取得发布tag/commit、发布制品/源码归档与dev-prod差异；只读保存原始输入，记录SHA256。未拿到完整源码，不确认目录能构建或原样复用。
2. 将12源码资产逐项确定KEEP/ADAPT/REWRITE/RETIRE，保留成熟内部算法、对协议/权限/代次作明确适配。原端点/文件数不是复用节省人日。
3. 对506接口清单导出运行时Java/Python路由（服务+方法+原始大小写路径+handler），排注释记录；逐调用方确定目标合同/适配/退役。新v1是内部边界，不能先删除旧入口。
4. DB导出脱敏SHOW CREATE TABLE等真实快照、索引/约束/触发器、字符集/排序规则、引擎版本与数据分布；逐表核对37/482实体盘点。dialogue先核create_by值域与身份关联，再以实际SQL/EXPLAIN决定索引。
5. 按三个事务边界设计授权版本、持久任务/outbox、激活指针/墓碑。共库expand-contract或新库迁移需书面定案；每表的新旧写入所有者、字段语义/缺省/回填幂等/兼容期/回退明确。
6. 同版本恢复副本运行正向/回填/回退；旧新程序分别核心读写，覆盖内容覆盖、迟到重试、删除/撤权、旧服务回退与历史引用。完成db-migration合同记录。
7. 每个批准决议包含owner、理由、目标合同、特征/兼容测试、证据哈希和外部批准引用；资料不足保留CANDIDATE_UNVERIFIED。严格reuse gate校验真实输入与引用，不以字段填了字就认为证明。

SOURCE-ASSETS/DATABASE-ASSETS 是状态登记，不是实际源码/DDL；REF必须指真实不可变材料，禁止生产凭据入库。Oracle工具只在另行批准的Oracle资料采集任务使用。

三个测量切片分别记录理解、边界适配、实现、回归、迁移的人日及失败原因，确认团队/运维资源后重估周期。没有数据不填90%或21周承诺。
