## 2 定位：坏在 **map 的事实投影**，不是 reduce 的语气/表述

打印该问法下 map 的输入面（`/tmp/show_facts2.py` 同口径）：

```

### L1-bae29a49 anchors=[] facts=3   triples=92
     北方重工配件厂 -信用评级-> AA / 江南装备科技有限公司 -信用评级-> AAA / 华东精密制造有限公司 -信用评级-> AA
### L0-18625408 anchors=[] facts=0   triples=72     ← 加点规则社区，一条都没进
### L0-60d6fa91 anchors=[] facts=2                  ← 只有两条评级
### L0-3af0d4bc anchors=[] facts=1                  ← 只有江南的评级
```
根因：`_project_facts` 的关系命中只做 **2-gram 字面重合**，而
问句里的「**基点**」与图里的关系名「AAA**级加点**幅度」**没有任何共同 2-gram** →
L0-18625408（72 条边，含 `智造贷 -AAA级加点幅度-> 30个基点` 等）投影出 **0 条事实**。
reduce 手上只有"江南=AAA / 华东=AA / 北方=AA"，没有"AAA→30 / AA→60"，于是对没把握的两个答 **0**。

**更严重的一点**：江南的 30 是**凭空来的**（它引用的 L0-3af0d4bc 里只有 `江南 -信用评级-> AAA`，没有 30）。
即"答对的那些也未必有依据"——这比全答错更容易骗过验收。

## 3 修复（三处，全部在 `graph_summary.py`，不改落库形状）

**① 概念归一**：`CONCEPT_ALIASES` 把同义说法收敛到同一概念，关系命中有两条路（2-gram 或概念）：
```
加点 ← 加点 / 基点 / bp / 幅度      评级 ← 评级 / 等级 / 级别
额度 ← 额度 / 限额 / 上限          期限 ← 期限 / 到期 / 有效期
利率 ← 利率 / lpr / 定价           还款 ← 还款 / 付息 / 还本
```
修后同一问法：L0-18625408 `facts=5`（AAA→30、AA→60、A→100 全部进来）。

**② 代码做确定性连接**（关键）：`_join_grade_rules()` 在代码里完成
`实体 -信用评级-> 等级` × `规则 -等级级加点幅度-> 数值`，产出
```
江南装备科技有限公司 -AAA级加点幅度-> 30个基点 [L0-18625408]
华东精密制造有限公司 -AA级加点幅度-> 60个基点 [L0-18625408]
北方重工配件厂 -AA级加点幅度-> 60个基点 [L0-18625408]
```
以【代码推导】段落喂给 reduce，并在 prompt 里声明"由两条图内事实组合，非外部知识"。
**理由**：这个连接是确定性的（等级相等即可），没有任何"理解"成分；交给 7B 只会引入随机性——
实测同一批事实下它给过 0 基点、也把 AAA 答成 60。

**③ 引用纠正 + 审计**：`_fix_bp_citations()` 只在"同一行同时出现该实体与该推导数值"时，
把社区号替换为**规则所在社区**；每处纠正写进响应的 `cite_fixes`，可逐条核对。
响应另增 `derived_facts`，评审可直接比对"模型表述"与"代码推导"。

## 6 这条缺陷的一般性（值得进 C15 验收项）

不是"某道题答错"，而是**"属性 → 规则"这类需要连接的问句，在换措辞后取值不稳定**。
可复用判据：*同一事实的 3 个同义问法，关键数值必须一致，且引用必须指向含该数值的社区*。
本次修复后该判据可稳定通过；未修复前 3/3 失败。

## 7 验收拆成两个独立指标（C 提议，采纳）

不合成一个"global 是否 PASS"，而是每个**数值结论**判三态，再汇总两个率：

```
PASS        本社区图事实含同一 "N个基点"        -> 数值有依据 且 引用正确
MIS_CITED   本社区不含、但别的社区含            -> 数值有依据 但 引用错位（修法：改引用对齐）
NO_SUPPORT  任何社区都不含                      -> 凭空生成（修法：改投影/生成约束）

数值可支撑率 = (PASS + MIS_CITED) / 总数    —— 生成层是否编造
引用正确率   = PASS / 总数                  —— 引用是否指到支撑该数值的社区
两者之差     = MIS_CITED 占比               —— 正好是"生成没问题、引用错位"这一类
```
现 kb_9 三问法实测：`3/3 PASS`，两个率均 **100%**。
修复前同一问法：`数值可支撑率 0%（0 基点那条 NO_SUPPORT）`、`引用正确率 0%（江南 30 那条 MIS_CITED）`——
两类错由同一个脚本分开报出，不会混成一句"GLOBAL 不通过"。

## 8 引用可回指 = 两段断言，缺一不可（C 的边界提醒）

```
① 传输正确：source 匹配 ^r12-rag/kb_9/…  →  presign(key=source) 200  →  取回对象 200
② 依据正确：数值 → 社区 id → Nebula 三元组命中（§7 的三态校验）
```
只做 ① 会掩盖"引对了文件、引错了块"：presign 200 只证明"对象存在 + 有读权限"，
不证明"这个块就是答案依据"。两段都过才算"引用可回指"。
