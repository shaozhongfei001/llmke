## 0. 先纠正一条我自己出过的错（否则后面的对照全是假的）

`platform/r12/graph/r14_b_probe.py --graph on|off` **只是标签，不改配置**：
经 `/qa` 时是否走图由服务端 `config_json.enabled_graph` 决定，payload 里的开关不生效。
实测证据：`--graph off` 那轮返回块的 `search_type` **仍然含 `graph`**（`['es','es','graph']`），
说明"on / off"两次跑的都是开图。**该组对照作废，不得引用。**

正确做法：在**检索层**（19995 `/retrieval_documents`）按请求参数 A/B，固定 rerank 与 top_k，
只改 `enabled_graph`。脚本：`platform/r12/graph/r14_b_graph_ab.py`。

## 2. "图带来增量"在本环境**不可观测**（不是"图无增益"）

受控 A/B（同一问句、rerank=true、top_k=10，只改 enabled_graph）：

| 问句 | 开图块数 | 关图块数 | 带 graph 标记块 | 只在开图出现的块 | 只在关图出现的块 |
|---|---|---|---|---|---|
| 单跳：AAA 加点多少基点 | 3 | 3 | **2** | **0** | 0 |
| 多跳：授信到期日 + 评级→加点 | 3 | 3 | **2** | **0** | 0 |

逐块身份比对（source + offset + 长度）结果：**两边完全相同，顺序也相同**。
开图只是在原有块上多打了一个 `graph` 标记，没有引入任何新块，也没有改变排序。

## 3. 归因（这是结构性问题，不是图算法无效）

kb_9 当前只有 **3 个文本块**（product-loan / product-intro / credit-ledger），而 `top_k=10`。
任何单路召回都会把全部 3 块拿回来，因此**块级增量在数学上不可能出现**：
即使图完全正确，它召回的也必然是这 3 块中的子集。

代价则是实打实的（同一问句）：

| 问句 | 开图耗时 | 关图耗时 | 增量延迟 |
|---|---|---|---|
| 单跳 | 24.3s | 4.3s | **+20.0s** |
| 多跳 | 50.2s | 19.8s | **+30.4s** |

→ 结论（口径校正）：**在本环境，图的增益不可观测**——kb_9 只有 3 个文本块而 `top_k=10`，
召回已把全部块取回，图再准也只能命中同一批块，所以"只在开图出现"必然为 0。这与"图算法无效"是两回事：
后者要证明"换了语料图仍然不带来新块"，我们**没有**这个证据，因此不写"图无增益"。

要让它可观测（属夹具，不属代码）：
1. 增加一篇**只被图命中**的跨主题语料（ES/Milvus 词面召回不到，但图上有实体/关系连过去）；
2. 把 `top_k` 压到 2~3，让单路召回**不满**。

在此之前，此项按**"本环境不可观测"**记录，不写成"不达标"也不写成"无增益"。

## 4. 两条判据必须分开记（避免混为一谈）

## 6. 生成侧两类问题必须分开写（不属图的问题）

| 类型 | 现象 | 判定 | 归因 |
|---|---|---|---|
| **A. 系统性取值错误** | 单跳 local 题：同一块内含 `AAA级加30个基点，AA级加60个基点，A级加100个基点`，4/4 次答 **60**（错）；多跳题答 30（对） | **稳定复现，跑几次都一样** | 7B 在"多值对照表"上稳定取第二项 |
| **B. 非确定性漂移** | global reduce 同题：C 跑 30/60/60、TL 跑 30/20/20 | **每次不同** | 生成侧采样非确定性 |

两者都在生成侧（C09/LLM），但**不能合成一句"跑几次就好了"**：A 类重跑不会自愈，
B 类才可能被采样掩盖（global 侧我已用 `temperature=0` + 固定 seed 压住）。

建议：local 生成侧加"实体属性 → 同名规则行"的显式约束（global 侧 `REDUCE_PROMPT` 已有同类约束）。

## 7 「仅图可达」夹具：`only_on=1` 成立（方案 C）

TL 批准的写法：

```
kb_9（3 块、top_k=10）：图的块级增量**本环境不可观测**（召回本来就满）
kb_26（4 块、其中 1 块词面/语义都不可达）：图带来 1 条仅图可达块（st=['graph']），增量可归因
=> 图的有效性依赖语料里存在"词面/语义都不可达但图上可达"的块
```

补一条**独立观察（生产默认参数下）**：

```
score_threshold 默认 0.05 时，图块（rerank 分 0.00135）会被筛掉 -> 生产路径上看不到图块
助手配置多为 0.001 时，图块能进
=> 是"取决于阈值"，不是结构性不可观测
```

### 7.1 方法论（TL 要求作为独立条目）：**"词面不可达" vs "语义不可达"**

| 版本 | 设计 | 关图是否召回目标块 | 说明 |
|---|---|---|---|
| kb_22 | 单篇直接写事实 | 召回 | 词面命中"归口/部门" |
| kb_25 | 拆段，目标块只有 25 字一句事实 | **召回（`st=['milvus']`）** | 拆句不够 |
| kb_26 | 210 字：7 段无关审计流程 + 末尾一句事实 | **不召回** | 稀释生效 |

一句话提炼：

> **"词面不可达"是工程问题（换词就行）；"语义不可达"是分布问题（必须让块向量被无关内容主导）。**

适用面不止图检索：**任何"仅某一路可达"的对照实验都会被这个坑咬**。
只要目标块自身语义与问句接近，无论词面怎么设，向量/混合召回都会把它带回来，
对照就退化成"两路都命中"，永远测不出那一路的增量。
