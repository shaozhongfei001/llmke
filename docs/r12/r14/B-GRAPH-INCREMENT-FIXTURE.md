# B-3 图增量夹具设计（TL 已批准做，属夹具不属代码）

## 1 为什么需要（先说清"不可观测"的成因）

现 kb_9 只有 **3 个文本块**，而 `top_k=10` → 任何单路召回都把全部块取回，所以
"只在开图出现的块"必然为 0。这不是图无效，是**测量条件**让增益不可观测。

要让它可观测，必须同时满足两条：
1. **单路召回不满**：`top_k` < 语料块数（否则召回必满）；
2. **存在"仅图可达"的块**：某块的正文与问句**词面/向量都不像**，只能沿图上的实体链到达。

## 6 这项能证明什么、不能证明什么

- 能证明：**当单路召回覆盖不全时，图能把"词面不可达"的块带进上下文**，并改变答案可用性；
- 不能证明：图的增益在任意语料上恒成立（单一夹具不构成统计证据）；
- 因此报告写法：*"在受控夹具上可观测到图带来 1 个仅图可达的块，并改变答案正确性；在现 kb_9（3 块/top_k=10）上不可观测。"* —— 两句并列，不互相替代。

## 8 实测结果（2026-10-27 13:56）：**夹具前提不成立，不得出"图有增量"结论**

四条前置验证当初都"通过"，但那是**只检查了"恒星项目"这一个词**；用**真正的验收问句**复测后暴露问题：

```
关图（enabled_graph=false, top_k=5）：
  01-project.docx  score=0.533  st=['milvus','es','es']
  02-dept.docx     score=0.400  st=['es','es']        <-- 目标块被**词面召回**
开图：3 条（01/02/03），02 也在
```

原因：验收问句「恒星项目的**归口部门**是哪个？」里的"归口/部门"出现在 02 正文（"启明计划**归口**装备制造**事业部**管理"），
ES 词面/向量都能命中 02 → **关图也能拿到目标块**，因此"开图包含 02"无法归因给图。

**这是 ④（关图对照）本该拦住的问题**。我原来的 ④ 用 `top_k=2`，恰好因为截断把 02 挤出上下文而"假通过"；
把 `top_k` 放大到 5 立刻暴露。**教训：④ 必须用与正式对照相同的 `top_k`，且必须检查目标块本身而非"总数"。**

### 10.4 副产物（C 判定后已更正）：不是 `top_n`，是 **`score_threshold` 绝对阈值**

我最初以为是 rerank 的 `top_n` 裁断，**错了**。C 复现并给出配置证据，我独立复跑一致：

```
top_n 默认 = 10（base.py:102 / reranker_service.py:238），3 进 1 出不可能是它
真因 = 绝对阈值：先 if rerank_score >= score_threshold 逐条筛，再 [:top_n]
默认 score_threshold = 0.05（nacos alg_common_py.yaml:48）

我的复跑（kb_26, 同问句, top_k=5, rerank=on）：
  th=0.001 graph=on  -> 2 条：01(0.08445) + 02b2['graph'](0.00135)
  th=0.001 graph=off -> 1 条：01
  th=0.05  graph=on  -> 1 条：01      <- 02b2 被阈值筛掉，与"看起来 only_on=0"完全一致
  th=0.05  graph=off -> 1 条：01
```

### 10.5 **口径更正（重要）**：生产路径并非"结构性不可观测"

原稿写的"生产路径（rerank 默认开）上图增量永远不可观测"**是错的**，已撤回。正确的是：

```
图块能否进上下文，取决于 score_threshold：
  · 默认 0.05（直连 /retrieval_documents 且未显式传阈值）-> 图块 rerank 分极低时被筛掉
  · /qa 走助手 config_json 的阈值，绝大多数配置是 0.001 -> 图块能保留
=> "不可观测"只在"阈值 >= 0.05 且图块 rerank 分极低"时成立，**不是结构结论**
```

按生产对齐口径（`score_threshold=0.001`，与 configId=1 一致）重测：
```
graph=on  -> 2 条，含 02b2（st=['graph']，score=0.00135）
graph=off -> 1 条
=> only_on = 1，与生产语义一致
```

### 10.6 纪律（合并成一句）

**任何"数量/集合"对照，必须把"会裁剪集合的参数"全部声明完毕**：
`enabled_rerank`、`score_threshold`、`top_k`、`top_n`、版本过滤。
少声明一个就能造出假 0 —— 本次就是被 `score_threshold` 的**服务端默认值**骗的，
我声明了 rerank、声明了 top_k，唯独漏了阈值。

另：`rerank` 打开后 `metadata.score` 被 rerank 分覆盖（0.8 → 0.08445），
**不能跨"开/关 rerank"比较 score**；比对同一批块请用 `source + offset + content 前缀`。
