# 源码利用策略 V1.0（目标：功能等价）

- 日期：2026-10-21
- 依据：业主明确「不管自读还是复制，最终都要实现原有平台系统的功能」
- 参照物：`docs/approvals/OWNER-RESOLUTION-2026-10-21-PRODUCTION-BASELINE.md` 认定的生产快照
- 性质：**策略建议，不是复用决议**。12 项资产的 `decision` 仍为 null，任何 KEEP/ADAPT/REWRITE/RETIRE
  都必须绑定特征回放用例与 owner 批准后才成立。

## 1. 把目标说准

“功能等价”不是“代码相似”。判据有三条，缺一不算完成：

| # | 判据 | 证据形式 |
|---|---|---|
| 1 | **行为对齐**：同一输入，旧系统与新系统输出一致（或差异可解释） | 特征回放用例 + 比对结果 |
| 2 | **边界合规**：新系统的外边界遵守新合同（OpenAPI/schema/错误码） | 合同测试 + 消费者回放 |
| 3 | **约束不退化**：授权、代次、坐标、幂等这些“看不见的行为”不因搬运而丢失 | 负例用例（越权/混代/撤权/迟到重试） |

只做第 1 条会得到“能跑但不安全”的系统；只做第 3 条会得到“安全但功能不全”。三条都要。

## 2. 代码利用的四档，按“目标功能一致”重排优先级

既然目标是功能等价，**能抄就抄**（抄是差异最小的路径），但要按“抄进来要付什么代价”分层：

| 档 | 做法 | 适用 | 代价 |
|---|---|---|---|
| **A 直取（COPY_AS_IS）** | 整个文件/模块搬进新边界 | 无框架耦合的纯逻辑：文本解析与分块、向量化封装、融合排序、敏感词匹配、prompt 模板、工具函数 | 最低；但必须做依赖体检（旧 Spring/py 版本、许可、硬编码路径） |
| **B 抄内核换外壳（ADAPT）** | 保留内部实现，外边界用端口/适配器重写 | 业务逻辑成熟但被旧 Controller/旧鉴权/旧配置绑死：KB 管理、索引写入、问答编排 | 中；要写适配器 + 合同测试 |
| **C 重写（REWRITE）** | 只参考语义，不搬代码 | 与新合同/安全约束冲突的部分：鉴权入口、SSE 证据绑定、授权逐路执行、代次与激活指针、offset/text_hash | 高；但**不改就是留缺陷** |
| **D 退役（RETIRE）** | 不迁移 | 功能被替代或确无调用 | 需调用方确认 + 影响面说明 |

**判断口诀**：先问“这段代码的**行为**是不是我们要的？”是 → A/B；再问“它的**外边界**是不是新合同要的？”不是 → 换壳（B）；再问“它的**隐含约束**（授权/代次/坐标）是不是安全的？”不是 → C。

## 3. 三类“抄了也不等价”的地方（必须改，不能为了功能一致而保留）

这三处是旧系统的**已知缺陷**，照抄会得到“看起来功能一样、实际不合规”的系统：

1. **鉴权**：旧系统用 token/会话，新合同要求签名 `AuthContext`（绑定服务、KB/文件范围、授权版本、有效期、请求标识）。
   抄旧鉴权 = 越权风险原样搬入（P0-03）。
2. **检索授权范围**：旧 `retrieval_graph()` 只传 `space_name/query/model/depth/top_k`，不携带文件范围；
   邻近块、图片回查、多版本扩召回会二次取数。抄这段 = 授权形同虚设（P0-03）。
3. **索引代次**：旧幂等键只有 `(kb_id, file_id, config_version)`，无法区分“同配置下内容被覆盖”；
   四后端各自切换、无统一激活指针。抄这段 = 新旧混代（P0-04）。

另外两处“抄了会丢精度”的：**offset 坐标体系**（必须 Unicode 码点 + 完整 `text_hash` + `parser_version`）、
**SSE 先核验后可见**（不能先推后补证据）。

## 4. 落地顺序（按“能端到端跑通的最小域”切，而不是按 12 个目录平均用力）

| 切片 | 范围 | 为什么先做 | 出口 |
|---|---|---|---|
| S1 解析→索引→召回 | CODE-01、CODE-04（部分）、CODE-03、CODE-11 | 这条链能独立跑（不依赖问答/图），最容易做出“同一文档同一问题，新旧召回结果一致”的证据 | 一份 parity 报告 + 3 类负例（越权/混代/撤权） |
| S2 问答与引用 | CODE-07、CODE-02、CODE-10 | 依赖 S1 的召回结果；要验证引用可点开、答案绑定类型化证据 | SSE 合同测试 + 引用回放 |
| S3 权限/网关/图 | CODE-05、CODE-12、CODE-08、CODE-09 | 权限是横切，最后收口；图可明确禁用（不阻断非图平台） | 六类授权负例 + 图路禁用说明 |

每个切片结束都要回答：理解/边界适配/实现/回归/迁移各花多少人日，**测完再谈周期**（不承诺 90%/21 周）。

## 6. 现实约束（决定“功能等价”能验到哪一层）

- **代码级对齐**（静态）：只要源码在就能做，现在就能做。
- **行为级对齐**（跑通回放）：需要 MySQL、ES、Milvus、Neo4j、LLM 服务与旧配置。
  **这些目前都没有**，所以“功能等价”的行为层证据暂时只能靠“读代码推导 + 单测级回放”，
  不能声称“新旧系统输出一致”。
- 因此每个 KEEP/ADAPT 决议必须写清：**这条等价性是用什么方式证明的**（跑通/推导/抽样），
  以及没证明的部分是什么。禁止用“代码一样”替代“行为一致”。

## 7. 一句话总结

> 以功能等价为目标，能抄就抄（抄是差异最小），但抄进来必须换壳、必须绑 parity 用例、
> 必须把旧系统那三处已知缺陷改掉；验收看行为与约束，不看代码相似度。
