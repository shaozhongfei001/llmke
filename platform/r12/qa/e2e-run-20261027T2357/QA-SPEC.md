## 1.2 判定四态 + 两种非判定态

```
PASS       页面里真实看见预期内容，且有可复核锚点
FAIL       可复现的期望/实际不符
BLOCKED    依赖的前置能力缺陷，无法进入
UNVERIFIED 缺入口/缺环境，无法判定（不得记 PASS）
NOT RUN    未执行（必须写原因）
ENV_EVENT  落在环境故障窗口内，本次结果作废，需重跑
```

**禁止**用"基本完成""应该没问题""看起来正常"结案。

## 1.3 HTTP 200 不能证明任何事

本系统已确认四类"200 但实际失败"，必须主动校验：

```
① 解析返回 success=true，但 task_statuses[*].success=false
   → 校验 task_statuses 全 true，且该 file_id 有 chunk、create_time 晚于请求时刻
② 并发上传，建索引 400 被吞，文件静默丢失
   → 逐文件确认入库，不得只看"上传成功"
③ 部署返回 200 实为 SPA fallback
   → 见 1.4 哈希比对
④ 摘要存储不可用被当成"知识库答不了"
   → 见 1.7 假拒答识别
```

## 1.4 第 0 步：证明你测的是哪一版（每个角色都要自己跑一遍）

```
A=$(grep -oE 'assets/index-[A-Za-z0-9_-]+\.js' frontend/plateform/dist/index.html | head -1)
curl -sS "http://127.0.0.1:18088/$A" -o /tmp/served-<角色名>.js
md5sum /tmp/served-<角色名>.js frontend/plateform/dist/$A     # 两哈希必须相同
```
不同（或返回约 23KB 的 index.html）→ 容器钉在旧 inode，**停下报告，不要继续**。

## 1.5 引用"可回指"必须三段全绿

```
① 形态  source 以 r12-rag/ 开头、无 scheme、无重复 host
② 传输  presign(key=source)=200，用签名 URL 取回=200（记录字节数）
③ 版本  source 中 /Vn/ == 当前有效版本（不是被替换掉的 V0）
```
只做 ①② 会得到假绿：判"引用可回指 PASS"，而用户点开的是旧稿。

## 1.6 表格/台账引用必须跨索引查

台账块只在 `table_chunks_kb_9` / `table_summary_kb_9`。只查主索引会把所有表格引用判悬空（假红）。

## 1.7 假拒答识别

问答返回「现有社区摘要不足以回答该问题」且 sources 为空时：

```
同批其它题也这样 + 摘要存储/索引服务刚重启  → ENV_EVENT，作废重跑
只有个别题这样 + 同批其它题正常             → FAIL（真缺陷）
```
不得把基础设施故障写成"产品答不了"。

## 1.8 环境故障先归因再定性

见 500/连接拒绝，先查服务在不在（端口、进程、pid 启动时刻），再决定 FAIL 还是 ENV_EVENT。

## 1.9 页面判定以"可见内容"为准

```
预览  判"页面里看得见内容"（canvas / 文本节点），不判接口状态码
文案  抓 toast/提示原文，不转述
列表  判具体行数与单元值，不判"页面没报错"
```

## 1.10 不得造假证据

```
不用拦截模拟"造"服务端故障冒充产品缺陷（若必须注入，明确标注"注入"）
不用人工改库的结果当产品行为
不用旧截图/旧日志顶替本轮结果
```

## 1.11 Playwright 技术规范

```
chromium，headless 可通过 HEADED=1 切换
每场景一个全新 BrowserContext（cookie/cache 不串场）
登录一次导出 storageState 复用，token 过期能自动重登
禁止 sleep/固定延时，一律 waitForResponse / expect().toHaveText
每 context 挂 page.on('response')，收集 4xx/5xx 与 >5s 慢请求
失败自动截图 + trace: 'retain-on-failure'
证据按角色隔离：<运行目录>/AG-x/evidence/<场景>/  *.png / network.har / console.log / assert.log
```

Playwright 已装（1.60.0，chromium）。脚本放 `<运行目录>/AG-x/`，用 node 或 python 均可。

# §5 已知陷阱（所有角色必读）

```
1. 用 title 比对版本会恒真（loan.docx vs loan(1).docx 是同一文件的两个版本）
   → 版本比对按 source 里 /Vn/ 之前的前缀归一
2. 只测"页面能打开"会验到旧包 → 必须哈希比对（§1.4）

4. 状态枚举（别读反）：task 1=PENDING 2=DEAL_ING 3=RETRY_ING 4=SUCCESS 5=FAIL；文件 99=未完成中间态
5. 表格文件的 table_chunks 条数是"该文件自己的表"，不是全库合计（台账单独只有 1 条）
6. Office 走 previewStream、xlsx 走第三方 viewer，失败文案机制不同，不要一条口径套全部
7. 批量作业期间若有人重启服务，会出现"解析成功但索引失败" → 记 pid 与启动时刻
8. 不要重启任何服务、不写 kb_9、不动 kb_22
9. 并发上传会因建索引冲突静默丢文件 → 写角色一律串行上传 + 逐文件确认
10. 客户端拦截造出的 500 必须标"注入"，不得与服务端真实故障混记
```
