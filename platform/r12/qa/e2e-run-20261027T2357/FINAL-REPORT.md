```

**可达链路（这是 P0 定性的核心）**：

### P0-3 UI 的 global 是假开关（AG-4 AG4-11）

```
POST /ai/question    「检索召回与模型推理，返回接口拼接在一起」-> publicQuestion()   含 global map-reduce 分支

```

### 4.2 四条可直接复用的判据

**先立一条证据分级（本轮最重要的方法产出）：**

```
一级（可作判定依据）
  HTTP 请求/响应实测（net 记录、状态码 + 响应体、presign 404 body）
  页面可见内容（截图、canvas 像素采样、DOM 文本）
二级（只作佐证，不得单独支撑结论）
  bundle 字面量 grep、源码阅读、构建时间戳

规矩：凡"某条路径调不调某接口"的结论，必须以一级证据为准。
理由（本轮正面用例）：同一个 presign 接口，用一级证据能把结论劈成两类——
  表格块引用 = 调了 presign 但键错（404/10002）
  详情页/内容抽屉 = 完全没调 presign
只凭"包里有没有 presign 字面量"这一条，两类会被混成同一个结论。
```

```
判定"包里有没有某段逻辑"
  主证 = 包内抠出对应代码 + 行为命中，两者能互相解释才算闭环
  佐证 = 该分支是产出该异常值的唯一来源
  旁证 = 源码 mtime vs dist mtime（只作旁证，单独使用会错——本轮 TL 就错过一次）
  注意：字面量计数只能证"代码在包里"，不能证"某条路径会走到它"；
        分支内的 return 顺序必须读 —— 最标准的反例：分支存在，但它排在 return 之后

判定"某现象的范围"
  必须先做全量枚举（dist/assets/*.js / 控制器全部映射 / 全部路由）
  否则只能写"在我查到的范围内"，不能写"只有/唯一/全部"
  —— 样本覆盖 ≠ 结论范围

判定"根因是什么"
  同一对象至少走两条入口对比，两条入口的差异本身就是根因所在
  —— 本轮实例：
      详情页能打开同一文件 / 引用链路打不开      → 根因是键构造不一致
      entry chunk 里有 / lazy chunk 里也有        → 根因是搜索范围不全
      正常 token 401 / 畸形 token 500            → 根因是兜底只兜了一半路径
  只走一条入口时，绝大多数人会写出"看起来合理但方向错"的根因（AG-3 初判即是）

判定"某结论已生效"
  必须来自产物自身内容（哈希 / 标识 / 数值），不能来自过程信号
  （HTTP 200 / 日志有行 / 命令返回 0）

判定"运行行为是否合规"
  代码只能来自**包内**（bundle 抠出）或**行为观测**；
  源码 + git 时间只能用来解释"为什么包内是那个样子"，不能用来判定运行行为。
  —— 本轮三次同型事故：
      AG-3 用 HEAD 源码推运行包 → P1 归因写成前端（已自查纠正）
      TL   用 dist mtime 推"包不含改动" → 被包内代码否定
      AG-4 用 HEAD 源码推运行包 → 把"包不含该逻辑"误判成"该调没调"

  同一结论的不同级证据可以并存，但要各司其职：
    时间差（二级）  → 证明"为什么只有这两处文件没进包"  → 管流程，可复用为发布纪律
    包内代码（一级）→ 证明"运行时到底调不调"            → 管事实，可复用为判定方法
  二级证据不是"没用"，而是"不能单独用来定事实"
```
