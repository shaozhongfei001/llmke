# W09 图清洗与跨文件桥接（INTEGRATION，真实库 g_kb_9）

## 问题

64 个有边实体里只有 1 个跨文件（日均存款），全图 4 个互不相连的碎片：
343 产品规则（72 边）· 329 客户额度表（18）· 333 指标口径（4）· 332 指标值（1）。
用户感知"每个文件一个图、没形成关联知识"，这个拓扑事实成立。

## 做了什么

```
① 句子型实体过滤（graph_types.sentence_like，进 is_valid_entity）
   命中 29 个："放款是智造贷办理流程的一部分" / "信用部分的最高额度为1000万元" …
   这类是整句被反序列化成实体，不能推理还污染社区摘要

② 金额变体归一（numeric_canon 已有，但历史数据没重建）
   人民币5000万元→5000万元、加60个基点→60个基点 …（5 个，均为孤立顶点，复制边 0）

③ BRIDGE-1 业务桥接（推导，不是抽取）
   依据：343 有「智造贷 -[适用对象]-> 制造业中小微企业」
   规则：客户所属产业链属制造业 → 该客户是此产品的适用客户
   命中 3 条：海川电子材料(电子信息) / 华东精密制造(汽车零部件) / 江南装备科技(装备制造)
```

## 实测

```
                    清洗前    清洗后    桥接后
实体/顶点             144     110      110
边                     95      86       89
连通分量                7       7        4
最大分量实体数          26      26       44
跨文件实体              1       1        2（日均存款、智造贷）
```

## 诚实边界

```
· 桥接边关系名写作「适用产品(推导)」，与抽取边可区分，不冒充抽取结果
· 北方重工配件厂没有『所属产业链』事实 → 不推导（缺前提不推导）
· 句子实体的处理选择"删除"而非"拆解"：删除安全，但会丢掉 9 条边里
  少数含真实信息的（如"办理流程-包含->审批"），这类应改由抽取侧产出规范三元组
· 跨文件实体只到 2，不是几十：329 与 343 本身没有共享实体，
  连通性改善靠的是推导边，不是清洗
```
