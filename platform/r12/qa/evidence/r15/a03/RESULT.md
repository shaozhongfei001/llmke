# A03 评级→加点推导的适用产品前提与加减符号（组件级，COMPONENT）

- 时间：2026-10-29
- 方式：直接调用 `_join_grade_rules`，用 D3/D4 形态的固定夹具
- 预期先固定，再看结果

## 预期

```
客户甲 AAA 适用产品A  -> 1 条 +30（产品B 规则 skip）
客户丙 AAA 适用产品B  -> 1 条 -30（减项符号保留）
客户乙 AAA 无适用产品 -> 0 条（规则分属两个产品，歧义 → 不推导）
```

## 实测

```
客户甲 -AAA级加点幅度-> 30个基点
客户丙 -AAA级加点幅度-> -30个基点
客户乙 (空)
skip 原因：'该产品不适用于此主体' / '主体缺少适用产品事实，且规则分属多个产品，无法确定'
判定 PASS
```

## 修的三件事

1. 原来只比等级不看产品（`_prod` 被丢弃）→ 同一主体会同时得到 +30 与 -30
2. `BP_RE` 不认负号 → "减 30 个基点" 被读成 "+30"；规则名含"减/下调"而值无符号时补负号
3. 主体无适用产品事实且规则跨产品时，按"缺前提不推导"处理，并在 `join_audit` 留原因
   （新增字段随 global 响应返回，供 A03 逐条核对前提）

## 局限

- COMPONENT 级：未走真实抽取链路，未在 UI 上验证
- 依赖抽取产出"适用产品"关系；若语料未抽到该关系，会退化为"歧义则不推导"，
  需在 W01/W02 的抽取侧确认该关系类型进入类型表
