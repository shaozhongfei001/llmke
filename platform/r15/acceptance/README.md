## 3. 反例法约定（关键）

1. 每条断言**至少带一个反例**，且反例判据由真实存储/接口算出，不靠文本相似度。
2. 反例命中即 `FAIL`；只验正例的断言在本目录不算合格（第 4 节表里"反例"列必须非空）。
3. **需要写操作的子项一律 SKIP**，并在 `reason` 里写清缺哪一步写操作；不真做。
4. 只读部分若已能证明缺陷，则该条直接判 FAIL（不等写操作），避免把已知缺陷藏进 SKIP。
5. 断言不允许"恒真"：没有数据的口径（如 kb_9 无逗号金额夹具）标为**未覆盖**并写进 detail，
   不算 PASS 也不假装验证过。

### 5.1 7 条 FAIL 的具体原因（均为反例命中，非"没跑"）

**A01 类型/归一**
- `N1` 图里出现白名单外的类型 `时间`（`ALLOWED_TYPES` 只有 16 类且不含"时间"，但 `RULES`
  会产出"时间"）→ 类型白名单不是硬约束。
- `N2` 合法评级 `正常` 被列进 `STOPWORDS` 当停用词丢掉（图中评级实体只有 `AAA/AA/关注`）；
  这正是 F07"合法值被过滤"。
- `N3` `contracts/ontology` 下 0 个受控文件，`ALLOWED_TYPES` 是源码里的字面量 16 类，
  M1 的 6 大类 27 码没有落成受控配置，谈不上"运行版本可追溯/可回滚"。
- 观测：133 个实体里 `unclassified` 51 个（38%）。

**A02 多关系与方向**
- `N1` `利率基准` 同一谓词两个方向都 `show_flag=1`：`1年期LPR -利率基准-> 智造贷` 与
  `智造贷 -利率基准-> 1年期LPR` 并存 → 仍是双向伪反向事实。
- 正例成立：93 条可见边、18 组端点对有多谓词；查询体已按 `show_flag='1'` 且只走
  `e:relationship`（N2/N3 通过）。

**A03 业务推导**
- `N2` 存储层就有反转：`智造贷 -最高额度-> 1000万元`（file_id=343）与
  `智造贷 -最高额度-> 8000万元` 同时存在，分项被当成了总额度事实入图。
